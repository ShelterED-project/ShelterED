# Контракт backend <-> AI-сервіс (ЧЕРНЕТКА)

> Статус: **чернетка, потребує погодження з Романом**. Backend -- клієнт AI-сервісу (репетитор і пояснення). Інші сервіси ходять лише через backend.
>
> Тривоги не входять у цей контракт: API повітряних тривог опитує й розбирає сам backend (епік B7), вебхука від AI-сервісу немає.

## 0. Загальне

- Усі виклики по HTTPS, JSON, UTF-8, час у UTC (ISO 8601).
- Мінімум персональних даних: у AI **не передаємо імен, класу, школи, email**. Лише псевдонімні id (`student_ref` = стабільний непрозорий хеш/UUID, який не розкриває користувача без backend) і необхідний навчальний контекст.
- Секрети (сервісний токен) лише в `.env`, не в логах.
- Помилки AI-сервісу: `{ "code": "...", "message": "...", "details": {} }`.

## 1. Пояснення: backend -> AI

Автентифікація: заголовок `Authorization: Bearer <service_token>` (сервісний токен backend, ротація через `.env`). Таймаут 10 с (tutor), 30 с (пакетна генерація); до 2 повторів з експоненційною паузою лише для ідемпотентних запитів і `5xx`/мережевих помилок; `4xx` не повторюються.

### 1.1 `POST /tutor/explain` -- пояснити іншими словами

Backend проксує `POST /tutor/ask` учня (схема `TutorAskRequest` у `docs/openapi.json`: `lesson_id`, `module_id`, `card_id`, `attempt_event_id`, без вільного тексту) після перевірки ролі та ліміту запитів і сам збирає `context` з уроку. Окремої сутності «тема» немає: `topic_id` поки = `module_id`.

```json
{
  "request_id": "0193a1b2-...",
  "mode": "explain_again",
  "student_ref": "s_7f3c9a",
  "grade": 7,
  "subject": "math",
  "topic_id": "0193...",
  "context": { "card_id": "0193...", "text": "Фрагмент матеріалу...", "previous_explanation_id": null }
}
```

### 1.2 `POST /tutor/explain` -- розбір помилок у тесті

```json
{
  "request_id": "0193a1b3-...",
  "mode": "test_review",
  "student_ref": "s_7f3c9a",
  "topic_id": "0193...",
  "attempt": {
    "attempt_id": "0193...",
    "questions": [
      { "question_id": "0193...", "text": "...", "student_answer": ["b"], "correct_answer": ["a"] }
    ]
  }
}
```

Відповідь (обидва режими):

```json
{
  "request_id": "0193a1b2-...",
  "explanation": "Текст пояснення...",
  "explanation_id": "0193...",
  "cached": false
}
```

Без діагнозів і оцінок стану дитини; AI не отримує даних опитування «як ти зараз?» у персоналізованому вигляді.

### 1.3 `POST /explanations/batch` -- кеш для пакетів

Celery-задача при публікації уроку запитує готові пояснення по темах; вони входять у пакет «Рюкзака».

```json
{ "lesson_id": "0193...", "topics": [{ "topic_id": "0193...", "text": "..." }] }
```

Відповідь: `{ "items": [{ "topic_id": "0193...", "explanations": [{ "explanation_id": "...", "text": "..." }] }] }`. Ідемпотентно за (`lesson_id`, версія контенту).

> Стан backend (05.11.2026): пакет «Рюкзака» вже має поле `explanations` (`PackExplanation`: `id`, `lesson_id`, `module_id`, `text`), але поки віддає порожній список — сховища закешованих пояснень і виклику `/explanations/batch` ще немає (B13.3). Пояснення входитимуть у хеш пакета, тож їхня поява створить нову версію пакета й push «рюкзак оновився».

### 1.4 Коди помилок AI-сервісу

| Код | Значення |
| --- | --- |
| `400 invalid_request` | схема не пройшла |
| `401 unauthorized` | невалідний сервісний токен |
| `429 rate_limited` | ліміт AI-сервісу (`Retry-After`) |
| `503 unavailable` | LLM недоступна |
| `504 timeout` | перевищено час |

Backend для клієнта віддає узагальнену помилку `503 AI_UNAVAILABLE` (формат помилок API) і підказує кешовані пояснення з пакета; падіння AI не ламає уроки, тести, перекличку.

## 2. Відкриті питання

- Як отримувати `student_ref` без розкриття користувача (HMAC від id з секретом backend?).
- Чи обовʼязковий `grade`/`subject` у запитах, чи достатньо `topic_id` (щоб не передавати зайвого).
- Ліміти запитів на учня, TTL кешу пояснень, ротація сервісного токена.
- Чи віддає AI власні `explanation_id` для кешу пакета, чи backend їх генерує.
- Опитування «як ти зараз?»: чи AI взагалі отримує відповіді (зведення без діагнозів), погодити з психологом.
