# ShelterED - Локальний сервер укриття

Цей сервер дозволяє проводити перекличку в укритті навіть без доступу до інтернету. Відмітки учнів зберігаються на ноутбуці вчителя й відправляються в хмару ShelterED, коли з'являється інтернет.

## Як запустити сервер (для вчителя):

1. **Один раз з інтернетом — підключіть сервер до ShelterED:**
   - Запустіть сервер (крок 3) і відкрийте `http://localhost:8080/teacher`.
   - Введіть email і пароль вчителя ShelterED та оберіть клас. Сервер завантажить список учнів і далі працюватиме без мережі. Пароль не зберігається.

2. **Увімкніть Wi-Fi точку доступу:**
   - Натисніть на іконку Wi-Fi у правому нижньому куті екрана Windows.
   - Перейдіть у налаштування "Мобільна точка доступу" (Mobile Hotspot).
   - Увімкніть її. (Назва мережі та пароль мають бути налаштовані заздалегідь).

3. **Запустіть сервер:**
   - Відкрийте папку з програмою (папка `ShelterED_Server`).
   - **Двічі клікніть на файл `ShelterED_Server.exe`**.
   - (З'явиться чорне вікно терміналу — це нормально, не закривайте його, поки триває урок!).

4. **Почніть перекличку:** на сторінці вчителя натисніть «Почати перекличку».

5. **Як учням підключитися:**
   - Учні підключаються до вашої Wi-Fi мережі.
   - Відкривають браузер (Chrome, Safari) і вводять адресу `192.168.137.1:8080` (або сканують QR-код з екрана вчителя).

## Як користуватися:
- **Для учня:** Сторінка `http://192.168.137.1:8080/` — учень натискає своє ім'я, потім «Я в укритті» або «Я в безпеці вдома». Відмітку можна змінити.
- **Для вчителя:** Сторінка `http://192.168.137.1:8080/teacher` — таблиця статусів учнів, стан синхронізації кожної відмітки та QR-код для швидкого підключення.

## Налаштування (змінні оточення)

| Змінна | За замовчуванням | Що це |
| --- | --- | --- |
| `CLOUD_API_URL` | `http://localhost:8000` | Адреса хмарного API ShelterED |
| `LOCAL_PORT` | `8080` | Порт локального сервера (8000 зайнятий бекендом) |
| `HOTSPOT_HOST` | `192.168.137.1` | IP ноутбука у Wi-Fi точці (для QR-коду) |
| `SYNC_INTERVAL_S` | `30` | Як часто синхронізуватися з хмарою, секунд |
| `LOCAL_DB_PATH` | `./shelter.db` | Файл бази SQLite |

## Як це працює (для розробників):
- **Backend:** Python, FastAPI, SQLAlchemy, Jinja-шаблони.
- **База даних:** SQLite (`shelter.db` створюється автоматично поруч із `.exe` або в поточній папці). Таблиці: `local_state` (id пристрою, токени вчителя, клас, стан синхронізації), `roster` (учні класу), `rollcall_session` (переклички), `rollcall_mark` (відмітки). **Схема змінилася: старий `shelter.db` треба видалити**, міграцій тут немає.
- **Синхронізація** (`sync_worker.py`) працює фоновим потоком разом із сервером (і в `.exe`); можна запустити й окремо: `python sync_worker.py`. Кожні `SYNC_INTERVAL_S` секунд, якщо вчитель підключений:
  1. оновлює access-токен (refresh-токен ротується, зберігаємо новий);
  2. оновлює список учнів і відкриту перекличку класу в хмарі (`cloud.py`, функція `fetch_roster`);
  3. реєструє локальні переклички `POST /classes/{id}/rollcall` з локальним UUID; якщо в хмарі вже відкрита інша (409), відмітки йдуть у неї;
  4. відправляє відмітки пачками до 100 подій `rollcall_status` у `POST /sync/events` (формат — `docs/sync-protocol.md`). Прийняті й дублі позначаються «Синхронізовано», відхилені — «Відхилено» з причиною й більше не повторюються; при помилці мережі чи сервера відмітки чекають наступного циклу.
- **Тести:** `python -m pytest -q` (потрібні `requirements.txt` і `pytest`).
- **Збірка `.exe`:** `pyinstaller --noconfirm ShelterED_Server.spec`.
- **Docker:** `docker build -t shelter-local . && docker run -p 8080:8080 -v shelter-data:/app/data shelter-local` (база в томі `/app/data`).
